# iOS 27 launch crash: build 1.0.0 (3)

**Date:** 2026-11-15 (crash reports) to 2026-11-19 (fix verified)
**Fixed in:** build 1.0.0 (4)

## Symptom

Build 3 crashed as soon as it opened, on both iPhone (iPhone18,2) and iPad
(iPad16,8) running iOS 27.2.1. There were four crash reports, all identical:

- Exception: `EXC_BREAKPOINT` / `SIGTRAP`, on the main thread
- Top frame: `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`
- Happens while iOS sets up the app's window, before any JavaScript runs

## Cause

iOS 27 stops any app that hasn't adopted the UIScene life cycle (a
`UIApplicationSceneManifest` in `Info.plist` plus a `SceneDelegate`).

Build 3 came from the code committed at the time, which used Expo 57. The
native iOS project Expo 57 generates doesn't adopt scenes. The `ios/` folder is
gitignored and generated by `expo prebuild`, so the fix has to come from the
Expo version, not from hand edits to `ios/`.

## Fix

1. Upgraded to Expo 58 / React Native 0.88.1. Expo 58's iOS template includes
   a `SceneDelegate` and the scene manifest.
2. Ran `npx expo install --fix` to align packages with Expo 58
   (`react-native` 0.88.1, `expo-status-bar` ~58.0.5,
   `react-native-safe-area-context` ~5.11.1, plus related patch versions).
3. Changed `app.json` for the Expo 58 migration: removed `newArchEnabled` and
   `android.edgeToEdgeEnabled`, and added the `expo-status-bar` plugin.
4. Set the iOS `buildNumber` to `4` in `app.json`.
5. Regenerated the native project: `npx expo prebuild -p ios --clean`.

## Verification

- Release simulator build (iOS 27.2): the built `Info.plist` contains
  `UIApplicationSceneManifest` with `AirGuard.SceneDelegate`, and
  `CFBundleVersion` is 4. The app launched to the Sensor Readings screen.
- Physical iPhone 11 (iOS 27.0), Debug build over USB with Metro running: the
  app launched, loaded the JS bundle and ran. The console showed no errors.
- Still to do: test build 4 from TestFlight on an iPad.

## Notes for next time

- A "No script URL provided" red screen on a phone just means a **Debug** build
  is running without Metro. Start it with `npx expo start`, or run the Release
  configuration.
- Any machine that builds the app must regenerate `ios/` after pulling, because
  it isn't tracked: `npx expo prebuild -p ios --clean`.
- Two Expo console warnings about the `fetch` and `remote-notification`
  background modes are harmless unless those features are added.
